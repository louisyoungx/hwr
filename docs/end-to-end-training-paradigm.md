# 无专家的端到端视觉—语言—双臂训练范式

> 状态：当前训练架构决策，后续训练实现以本文为准
>
> 决策日期：2026-08-10
>
> 适用范围：三维仿真、本机训练、未来真机数据与部署

## 1. 结论

平台不再用手写专家、规则轨迹、人工示范或另一个教师策略给 Actor 提供动作答案。双臂 Actor 直接与环境交互，根据任务最终结果学习：

```text
程序化场景与任务 ───────────────────────────────┐
                                                v
多相机数据 -> 视觉预处理 ──┐              仿真/真机环境
自然语言指令 -> 文本编码 ──┼-> 双臂 Actor -> 安全层 -> 执行动作
机器人本体状态 ────────────┘       ^                   |
                                    |                   v
                                    └── 强化学习更新 <- 结果奖励
                                             ^
                                             |
                                  训练期特权 Critic
```

Critic 可以在训练时读取仿真真值来估计动作价值，但它不产生动作、不生成示范，也不被 Actor 模仿。部署时只保留视觉预处理、文本编码、Actor 和独立安全层。

这项决策取代以下旧路线：

- 手写航点、抓取姿态、任务阶段和规则专家；
- 用规则专家或人工遥操作轨迹进行行为克隆预热；
- 用教师策略生成 DAgger 纠偏标签；
- 将“找到、接近、抓取、放置”等技能序列作为训练监督；
- 把单臂脚本扩展成所谓双臂训练数据。

历史行为克隆和专家代码只可用于回归旧实验或检查物理引擎，不得进入正式训练数据、初始化 checkpoint、奖励计算或评测动作链路。

## 2. 人工监督边界

### 2.1 人工只定义结果与边界

每类任务只人工定义一次：

- 可随机采样的初始状态范围；
- 自然语言任务意图；
- 可由环境状态自动计算的成功与失败条件；
- 碰撞、关节限位、速度、力矩等安全约束；
- 训练集与隐藏评测集的分布边界。

例如“把餐盘和杯子放入指定收纳位”的成功判据只检查 Episode 结束后的容器关系和稳定时间，不规定机器人先拿什么、用哪只手、从哪里抓、走哪条路径。

### 2.2 禁止的人工标签

正式训练不得要求人工提供：

- 每帧或每段动作标签；
- 专家轨迹、纠偏动作或遥操作示范；
- 抓取点、末端航点或底盘路线；
- 任务阶段、技能名称、对象 token 或目标 token；
- 左右臂分工规则；
- 按场景编写的控制状态机。

仿真器自动产生的成功、终止、安全事件和 achieved goal 属于环境反馈，不是动作标注。这些字段用于奖励、Critic、回放重标记和审计，不能进入 Actor 输入。

## 3. Actor 运行时契约

### 3.1 可见输入

Actor 只能接收：

- 经过确定性预处理的头部 RGB-D、左右腕部 RGB 及有效性信息；
- 最近若干帧视觉历史；
- 原始自然语言指令经本地文本编码器产生的向量；
- 底盘、左右机械臂、左右夹爪的本体状态；
- 最近实际执行动作；
- 时间戳、丢帧掩码等不包含任务答案的质量信息。

以下信息禁止进入 Actor：

- 仿真物体或目标真值位姿、接触真值和成功标志；
- 奖励、Critic 特征、任务进度和未来动作；
- 脚本状态、阶段、技能、对象 ID 或人工计划；
- 仅仿真可获得、真机无法复现的任何字段。

### 3.2 双臂联合输出

Actor 每个控制时刻联合输出 16 维基础动作：

```text
[底盘线速度, 底盘角速度,
 左臂基座坐标系 6D 末端 twist, 右臂基座坐标系 6D 末端 twist,
 左夹爪目标, 右夹爪目标]
```

每臂 6D 分量依次为末端线速度 `vx, vy, vz` 和角速度 `wx, wy, wz` 的归一化命令。运行时适配器用阻尼最小二乘或设备 SDK 的等价控制器转换为关节伺服目标；转换只使用机器人运动学和当前关节状态，不接收物体位姿、抓取姿态、任务阶段或技能计划。

部署动作头的硬边界为底盘线速度 `±0.18 m/s`、角速度 `±0.50 rad/s`，左右臂每个归一化 twist 分量 `±0.35`；MuJoCo 适配器再映射到最大 `0.30 m/s` 线速度和 `1.0 rad/s` 角速度。在线探索与 Actor 输出必须共享这组边界，避免策略利用 Critic 外推误差生成训练域之外的动作。

网络可以一次预测未来若干步的 `H × 16` 动作块。左右臂没有主从关系，不允许运行时固定一侧、由场景代码选择活动手，或在 Actor 外部插入换手逻辑。

安全层独立执行关节、速度、力矩、碰撞和动作有效期限制。安全层可以拒绝动作，但不能替策略完成任务。

仿真适配器在提交动作前用一个控制周期的物理副本检查严重碰撞；真机适配器使用关节限位、力矩/电流和近距传感器实现同一拒绝语义。屏障只能把危险动作替换为保持动作，不能朝任务目标修正动作。replay 和动作历史必须记录安全层实际执行的 16 维动作，并单独累计干预次数，不能把已拒绝的 Actor 提案当成环境因果。

训练期另设 Safety Critic，输入特权状态和 Actor 原始提案，监督信号只来自确定性安全屏障的“接受/拒绝”结果。它给 Actor 提供安全成本梯度，但不进入 Actor 输入、不导出到部署模型，也不替代运行时屏障。奖励 Critic 仍只用实际执行动作估计环境因果，Safety Critic 只用提案估计约束风险，二者不得混用。

## 4. 视觉与语言先验

### 4.1 确定性视觉预处理

每个 Episode 保留原始帧、标定参数和时间戳；策略输入由统一管线派生：

1. 同步头部、左右腕部相机与机器人状态并生成缺失掩码；
2. 使用内外参去畸变，对齐 RGB 与深度；
3. 清理无效深度、孤立噪点和工作空间外数据；
4. 转换到统一机器人坐标系，构造稀疏点云或等价三维表示；
5. 分别裁剪、缩放和归一化全局与局部视野；
6. 组合短时历史并标记重复帧、丢帧和相机不可用状态。

预处理配置随 checkpoint 保存。训练、闭环评测和真机部署必须加载同一版本。

### 4.2 无动作标签的视觉学习

视觉前端随 Actor 联合训练，并可以从策略自行采集的帧使用自监督辅助目标：

- 深度重建和时序一致性；
- 跨视角、跨时间对比学习；
- 遮挡恢复和相机运动预测；
- 仿真自动输出的分割、深度或光流辅助损失。

辅助输出不构成对象列表或符号任务计划。仿真标签不能回流到 Actor 输入。

### 4.3 自然语言先验

语言先验来自可在本机运行的预训练文本编码器，而不是手写指令解析器。任务生成器同时采样环境目标和多种自然表达，二者只通过 Episode 最终奖励建立落地关系，不附带动作序列。

首阶段冻结文本编码器；数据充足后只微调上层或使用低秩适配。编码器权重、分词器和哈希随 checkpoint 登记，训练与部署不依赖在线服务。

## 5. 无专家强化学习闭环

### 5.1 直接训练 Actor

主算法采用目标条件化的非对称离策略 Actor-Critic。第一版以连续动作、最大熵探索和经验回放为核心；Actor 从随机策略参数或无动作标签的视觉/语言预训练参数开始，禁止从专家或教师 checkpoint 初始化。

随机 Actor 的最终动作层使用近零小幅随机权重和零偏置初始化，使底盘、双臂与夹爪的初始均值动作位于中性点附近，正负探索具有相同机会。该初始化不读取任务、环境或动作样本，不编码姿态或轨迹；随机权重幅度作为模型配置写入 manifest，保证重载和训练谱系可审计。

- Actor 只读第 3.1 节的可部署输入并直接输出双臂动作；
- Critic 训练期可读完整机器人状态、物体位姿、接触和环境目标；
- Critic 只输出价值估计，不输出动作或中间计划；
- 奖励只由任务结果、安全约束、时间和能耗计算；
- Actor、Critic 都不得读取人工任务阶段或脚本动作；
- 导出时彻底移除 Critic、奖励器和仿真真值。

Critic 更新先把环境奖励缩放到稳定的价值范围，并对随机动作及当前 Actor 的分布外动作施加保守 Q 正则，抑制 Actor 利用 replay 未覆盖动作的虚高价值。Actor 优化双 Critic 估值的较低值，而不是任取一个价值头，避免利用单头估值误差。该约束只压低未经物理数据支持的价值估计，不把 replay 动作当监督目标，也不引入行为克隆损失。

在线策略使用可重参数化的 squashed Gaussian：动作网络给出状态条件化均值，训练器持有可学习的逐维方差；底盘和双臂样本经 `tanh` 映射到物理边界，夹爪样本经 `sigmoid` 映射到 `[0, 1]`。运动速度与夹爪分别配置方差边界：前者保持小幅连续扰动，后者覆盖接近二值的开合，并在若干控制步内保持同一个采样值，以匹配手指伺服和建立接触所需的物理时间。保持器只读动作流和固定持续时间，不读任务或环境。Critic bootstrap 和 Actor 更新都包含变换后概率密度与熵正则，使同一视觉状态在训练期持续保留多个可行动作模式，而不是只依靠确定性均值外加局部噪声。部署导出仅保留动作均值网络并执行确定性推理；训练方差、熵项和 Critic 不进入运行时。

约束学习采用双时间尺度更新：奖励 Critic 和 Safety Critic 每个训练批次以 `3e-4` 更新，Actor 每 10 个 Critic batch 才更新一次。Actor 前 6500 个 Critic updates 使用 `3e-5`，获得足够快的 frontier 保持学习；之后降为 `1e-5`，防止已形成的空间策略继续漂移到高幅、未校准动作区域。衰减只读取全局优化步数，不读取任务、接触、目标或阶段；初始/最终学习率、衰减点和逐 Episode 实际学习率都写入训练配置、manifest 与记录。时间尺度不要求 Actor 复现 replay 动作，也不引入旧策略或教师的一致性损失。

物理伺服、接触建立和安全拒绝通常跨越多个 20 Hz 控制步。Replay 因此保存固定时间窗的多步折扣回报、对应未来状态和实际 bootstrap 折扣，使 Critic 直接看到一个动作在后续物理窗口内造成的结果；窗口遇到 Episode 终止立即截断。多步回报只重组环境已经产生的奖励和状态，不生成动作目标，也不改变 Actor 的可部署输入。

正式训练默认使用每个任务定义的完整物理时域：托盘和收纳篮 1200 个控制步（60 秒），回弹抽屉 1600 个控制步（80 秒）。命令行可以显式设置更短上限做算法诊断，但这类 run 不得用于成功率、稳定保持或单臂消融验收，避免在双接触和搬运结果出现前人为截断回报。

### 5.2 自动任务分布与课程

环境从配置化分布自动采样房间布局、物体、容器、语言表达和物理参数。课程调度器根据滑动窗口成功率自动调整难度，不给 Actor 增加阶段输入：

1. 从短距离、少遮挡、低噪声的完整任务分布起步；
2. 成功率进入目标区间后扩大初始位置、姿态和视觉变化；
3. 成功率下降时提高易样本比例，但不回退为脚本控制；
4. 持续混合历史难例，避免只会当前课程层级。

课程是初始状态分布的变化，不是把任务拆成由人指定的动作步骤。

训练接口必须满足一条硬边界：策略动作只能来自随机探索或当前 RL Actor，训练代码不得按场景生成动作。新场景只能提供观测、动作空间、奖励、终止、环境定义的成功/安全结果，以及合法环境变换；不得为托盘、篮子、抽屉或其他对象增加专属训练分支。成功条件和安全约束属于环境任务接口，可以读取仿真真值，但不能返回下一步动作、抓取姿态、航点或技能阶段。

自动 frontier 只保存当前随机 Actor 或学习 Actor 实际访问过的物理状态，并用四类任务无关信号排序：归一化 Critic 状态的新颖度、当前双 Critic 的 TD error、Episode 回报相对该任务历史均值的改善速度、失败轨迹最后一个安全状态。四类信号按各自历史百分位归一化，分数签名只表示哪类学习信号占主导，不表示左手、右手、接触类型或对象类别。安全代价大于零的状态不能进入候选。系统不读取到达距离、目标坐标、接触签名或人工几何阈值，也不生成动作答案。

Frontier 快照保存广义位置、速度、加速度、执行器当前控制载荷和适配器不透明求解器状态；这些是已经发生的动力学状态，不是未来动作。被选中后只执行一次无动作的状态恢复一致性校验：比较后端指纹、广义位置和速度，不运行闭夹爪、移动手臂或其他探针策略。校验失败就回到原始 reset。候选池、来源 Episode/step、学习信号、选择次数和迁移审计随 checkpoint 保存；隐藏评测与最终视频始终使用原始程序化 reset。旧 checkpoint 中由手写距离/接触阈值产生的 frontier 条目在迁移时全部丢弃，不参与新课程。

奖励在连续结果量上增加双侧近邻占用项 `0.02 * exp(-max(d_left, d_right) / 0.08)`。它不判断任务阶段、不读取对象类别，也不提供动作方向；作用只是让从自主 frontier 开始的策略在两臂都接近时仍获得小额正反馈，而不是因为势函数差分在 reset 时归零便立即离开。任一侧仍远至 20 cm 时，该项小于逐步成本，不能靠停在单臂或远距离状态刷分；真实双侧接触、任务结果和安全约束仍有更高权重。

物体到目标的位移进度不得在未受控状态下直接计分。托盘和收纳篮只有在相邻两个物理时间步都存在左右臂同时接触时，才累计这段时间内的目标距离缩短；任一接触丢失就撤回尚未转化为任务成功的累计搬运进度。回弹抽屉的开度同样只在左臂连续接触抽屉把手时累计，物品位移仍要求双侧各自保持对应物理接触。累计量作为训练期 Critic 状态的一部分，使奖励过程保持可辨识，但不进入 Actor 观察。该约束只判断连续物理因果，不生成抓取姿态、任务阶段或动作标签，阻止未抓持推物、撞开抽屉后再碰一下等方式套取进度奖励。

到达距离、接触步数、同步接触窗口等物理量仍可写入逐 Episode 诊断，帮助人判断机器人是否真的在做事，但不得再影响 frontier 准入、任务采样、replay 分层或 Actor 更新。

多任务采集使用同一组任务无关信号分配采样预算：状态新颖度、TD error、奖励改善停滞和失败边界强度越高，任务获得的后续采集概率越高；所有任务保留固定概率下限。不同量纲先转换为任务间秩次再组合，因此接入新场景不需要新增距离尺度。任务抽样、frontier 选择和动作探索使用独立随机流，调度器不输出动作，也不向 Actor 暴露任务阶段或采样分数。

### 5.3 目标重标记与失败利用

失败 Episode 原样进入可追踪 replay buffer。环境自动提取 Episode 实际达到的最终关系，用 hindsight goal relabeling 将部分失败轨迹重标记为其他有效目标；整个过程不产生人工动作答案。

回放先按任务隔离容量并均衡抽取，再为失败返回、归一化状态变化中秩次最高的新颖样本、环境奖励中秩次最高的改善样本，以及安全层实际拒绝的提案保留独立比例。分层只使用 transition、环境奖励与安全代价，不读取对象类别、到达距离、接触类型或目标几何。所有分类只影响采样和 Critic 更新，不进入 Actor 输入，也不产生动作监督。

连续动作的主体探索来自 Actor 自身的最大熵分布。冷启动随机阶段和低概率全局 burst 仍可利用机器人左右同构这一结构先验：部分末端扰动按 x-z 平面反射成对采样，部分夹爪开合成对采样，其余样本保持左右独立。采样器不得读取相机、语言、物体状态、环境目标、任务 ID 或阶段，也不提供应当执行的动作；它只改变无标签探索分布，使双臂并发状态不再依赖两个独立随机过程偶然同时命中。

物理夹爪从发出闭合命令到钳口与物体形成稳定接触需要真实的伺服和接触收敛时间。动作探索因此加入“执行器静置”样本：在固定窗口内把底盘和双臂速度置零，并按显式 Bernoulli 概率保持两个夹爪的开闭命令；夹爪按同一左右同构先验随机选择成对或独立采样。除逐步低概率静置外，还可以按固定概率在 Actor Episode 的第一个控制步开始静置，避免策略先把自主发现的稀有物理姿态带偏。该过程不读取观测、任务、目标、接触、奖励或阶段，也不根据物体状态决定何时闭合；它只是让 replay 同时覆盖持续运动和静止收敛两类真实执行器动力学。逐步概率、首步概率、窗口长度、闭合概率、零运动约束和夹爪配对方式必须写入 action-exploration 审计，评测时完全禁用。

平台允许从已通过哈希和无专家谱系校验的 checkpoint 创建新 run；普通 fork 只能改变总 Episode 数、受容量约束的 replay 上限、任务无关动作探索、frontier reset 混合概率、回放比例和通用无标签一致性权重。Actor、Critic 与普通 replay 可以继承；与当前课程 schema 不一致的旧 frontier 和任务采样历史必须明确丢弃并计数，不能把旧距离阈值的结果伪装成新课程发现。

若某个任务的场景资产、初始几何关系或动力学分布发生实质变化，旧 transition 和物理快照不再与新环境同分布，不能借普通 fork 混入训练。此时必须通过显式的 `--reset-task TASK_ID` 创建审计分叉：仅丢弃该任务的普通/失败/发现/物理进展/安全 replay、frontier 快照、任务采样历史和随机化课程窗口；其他任务状态与共享 Actor/Critic 参数继续继承，父 Episode 只作为历史谱系保留。Lineage 必须记录被丢弃任务、各 replay 分层计数、frontier 数量、采样历史、课程状态和分布变化原因。任务重置不会产生动作、阶段或标签，也不得被用于选择性删除失败结果。

最大熵目标按执行器性质分开：底盘与双臂连续运动温度为 `0.02`，双夹爪温度为 `0.002`；夹爪初始 log-std 为 `-0.5`，范围 `[-3.0, 0.2]`。夹爪仍保持随机开合探索，但不会为了追求与 14 维连续运动相同的熵而长期维持接近 1.0 以上的潜变量标准差，从而破坏已经到达把手附近的闭合窗口。该设置不规定何时闭合，也不读取接触或任务阶段；闭合均值仍由 Actor-Critic 从结果奖励中学习。

Actor 的 16 维联合动作均值和动作方差使用同一个基础学习率，不对夹爪梯度或参数组做额外倍增。早期 Critic 对夹爪开合的局部排序仍会变化；放大夹爪更新会让 Actor 在价值排序校准前过快漂移，并经真实闭环和动作历史间接破坏双臂空间控制。训练因此只通过结果 Q、较低夹爪熵温度和正确的执行器正则边界来学习开合，不使用按任务、接触或阶段触发的学习率捷径。统一学习率由单元测试锁定。

动作幅值和逐步变化正则只作用于底盘与双臂 14 维连续运动，不作用于两维夹爪位置。夹爪开合本来就需要从一个位置切换到另一个位置；若把它纳入连续速度 slew penalty，reset 后的零动作历史会系统性地把策略拉向全开并抵消 Critic 的闭合价值。夹爪的物理平滑由固定 12 个控制步的无任务保持器完成，它只延续 Actor 已输出的值，不决定何时开合。运动/夹爪正则边界由单元测试锁定。

局部相关噪声之外，训练保留低概率、短持续的全动作空间随机 burst，防止 Actor 到达动作边界后 replay 永久局限在单一局部邻域。Burst 仍只使用动作边界、持续时间和左右同构反射，不读取任何任务或环境字段；运行时安全层照常筛选每个提案，实际执行动作和拒绝事件进入各自回放字段。

### 5.4 防止单臂塌缩

仅在动作向量中预留双臂维度并不足够。任务分布和验收必须让双臂协作具有不可替代性：

- 仿真环境通过统一运行时契约声明合法变换，例如横向反射；通用增强库按变换 ID 同步处理相机、本体、Critic 状态和动作，训练器不认识“托盘”“篮子”或“抽屉”。未声明的变换一律不应用。EMA Actor 一致性目标仅由同一合法变换自动构造，不含人工动作标签；
- 随机交换物体和把手所在侧，消除固定惯用手捷径；
- 加入必须同时保持两个接触点的宽托盘、双把手容器等任务；
- 加入一只手保持回弹抽屉、另一只手放入物体的并发任务；
- 记录左右臂有效接触、持物时间和并发操作窗口，但不因“动过两只手”直接奖励；
- 评测时分别锁定左臂和右臂做消融，验证双臂任务不能由单臂绕过。

普通任务允许策略自行判断单臂是否足够；平台不为了表面动作对称而强迫两只手无效摆动。

### 5.5 闭环数据流

```text
完整/前沿 reset -> Actor 探索 -> 结果/安全奖励 -> replay -> Actor-Critic 更新
       ^               |                                  |
       |               ├-> 失败与 achieved goal 自动回流 |
       |               └-> 已访问物理前沿状态 ------------┘
       └--------------- 自动课程与难例重采样 --------------
```

行为克隆损失、专家动作误差和教师一致性损失不属于正式训练指标。

## 6. 本机训练与可复现性

全部训练必须能在现有本机完成，不依赖远程推理 API。训练器可自动选择 MPS、CUDA 或 CPU，并必须：

- 使用多环境并行、经验回放、低分辨率起步和混合精度控制计算量；
- 保存任务分布、预处理配置、文本编码器、模型配置、随机种子和代码提交；
- 周期保存 Actor、Critic、优化器、温度参数、课程状态和 replay buffer，支持中断续训；
- 导出不含 Critic 和特权字段的部署 checkpoint；
- 从磁盘重载部署 checkpoint 后执行闭环评测；
- 按 Episode、布局、物体实例、语言表达和随机种子隔离训练与评测。

## 7. 当前实施顺序

1. 冻结 16 维双臂动作、ActorObservation、环境目标和奖励契约；
2. 打通 MuJoCo 左右臂、左右夹爪和底盘的联合控制，删除固定收纳侧手臂的运行时路径；
3. 实现程序化任务采样、终局成功判据、安全惩罚和 achieved goal 提取；
4. 实现无专家的目标条件化非对称 Actor-Critic、replay 和断点续训；
5. 先在低视觉随机化下直接训练双臂 Actor，再自动扩展布局与视觉难度；
6. 加入左右镜像和物理上必须双臂协作的任务，完成单臂消融；
7. 在至少三个家务场景、未见布局和未见语言表达上闭环评测；
8. 生成未经剪辑的视频、输入审计、训练谱系和消融报告。

旧专家调试不再阻塞上述顺序，也不能作为任何阶段完成证据。

本机闭环验收命令（训练完成后）为：

```bash
hwr-evaluate-bimanual-rl runs/bimanual-rl/<run-id> \
  --seed-count 20 --video-seed-count 1
```

该命令默认对三个场景分别执行正常、锁左臂、锁右臂三组评测；第三人称、头部、左腕和右腕视频由同一评测进程逐控制帧同步写出，不做剪辑或补帧。`report.json`、`acceptance.json` 和 `manifest.json` 保存逐 Episode 结果、固定门槛、训练 manifest 哈希、Actor 哈希、未见种子及视频哈希。

## 8. 阶段验收

一个训练阶段只有同时满足以下条件才算完成：

- 训练谱系证明没有加载专家数据、遥操作动作、教师 checkpoint 或动作标签；
- 自动化测试证明 Actor 输入不存在特权字段和人工阶段/技能字段；
- 同一原始观测经相同配置得到确定一致的视觉预处理结果；
- 每一步策略动作同时包含底盘、左右臂和左右夹爪输出；
- 部署 checkpoint 能在没有 Critic、奖励器和任务控制脚本的进程中运行；
- checkpoint 从磁盘重载后，在隔离种子上执行闭环动作；
- 双臂必需任务达到成功门槛，锁定任意一臂后无法通过同一门槛；
- 视频、Episode、模型哈希、代码提交和配置能够相互追溯。

旧行为克隆损失下降、专家脚本成功、训练种子复现或两只手臂发生过运动，均不构成训练完成证据。
