# R0001 独立评审与筛选

## 评审规则

两名筛选 Agent 在互不查看对方结论的条件下，分别核验 `01-proposals.md`、当前实现、
配置和历史负证据。每项按 1～5 分评估：

- 目标价值；
- 证据强度；
- 可检验性；
- 因果可归因性；
- 通用性；
- 实施成本，5 表示成本低；
- 回归风险，5 表示风险低。

总分只用于压缩信息，不作为机械排序依据。评审优先拒绝评测泄露、任务捷径、安全降级、
不可证伪、多变量捆绑及没有当前基线支撑的改动。

## 共同反驳

### 对 `R0001-P01`

- 单个固定 seed 只能建立当前谱系的可复现校准基线，不能估计 run-to-run 方差。
- 连续两个周期使用累积 Replay 和同一留出，不是两个独立实验。
- 探索 Actor 解锁只说明准入证据成立，不代表三个家庭任务闭环成功。
- 若 24 Episode 未解锁，只能说明固定校准预算内失败，不能证明完整训练永远失败。

### 对 `R0001-P02`

- 候选训练尺度与正式系统辨识留出的四个尺度完全重合，存在分布级 benchmark 对齐和
  Goodhart 风险；仅 seed 隔离不够。
- 必须增加未参与候选设计的确认激励族或未见相关尺度，且不能用确认集调参。
- probe ratio 可能通过恶化 state-only 分子上升；必须同时冻结 state-action 绝对误差
  非劣界。
- 相关尺度计划必须与任务交叉平衡，避免任务和尺度周期性绑定。
- 低相关动作可能增加 jerk、安全改写和提前终止；RMS 与位移守护不足以单独排除风险。

### 对 `R0001-P03`

- 改变任务顺序也会改变任务和全局 Episode seed 的配对，必须建立逐任务 seed bank。
- 总 Episode 相同不保证 retained transition、接触、安全样本或实际执行动作分布相同。
- 若只改善 bootstrap 下界，应归因为统计功效，而不是能力提升。
- 启动物理 run 前应先在冻结 Replay 上做均衡子采样功效分析。

### 对 `R0001-P04`

- 该问题是评测统计合同错误，不是能力问题。
- 同步 bootstrap 可能提高 `ratio_p05`；由此产生的门禁变化只能标为评测合同迁移。
- 必须验证覆盖率、零效应假通过率、单 horizon 失败检出率和 Monte Carlo 稳定性。
- 新旧统计必须使用同一冻结数据双报告；点估计、MSE、Episode 列表和门槛不得变化。

### 对 `R0001-P05`

- 把重复窗口改成不同 Episode，会同时把每 update 的唯一窗口数从约 1 提高到 2；结论应
  表述为 batch 组成机制，不能直接宣称数据效率提升。
- 第二样本必须优先保持同任务、同视觉监督或碰撞 strata，只改变 source Episode。
- 固定 1,600 update 才是主要比较；首次解锁时间只能作次要指标，不能提前终止一组。
- 必须记录唯一窗口、source Episode、任务、shard、I/O 和墙钟时间。

### 对 `R0001-P06`

- 训练目标直接复刻正式 audit 的真实/打乱动作、物理模态和 `1/4/8/16` horizon，存在
  严重目标函数泄露。
- 排序损失可能仅放大错误动作误差；必须守护真实动作绝对误差。
- 权重、margin、扰动和聚合方式提供过多设计自由度，当前轮不宜优先投入。

### 对 `R0001-P07`

- 相同整数 seed 不代表 Python `random` 与 NumPy RNG 存在统计相关。
- 当前只有确定配对，没有可复核的混淆证据。
- 单个无固定点置换的差异更可能是 Monte Carlo 波动；不得挑选最佳置换。

### 对 `R0001-P08`

- 实际执行动作混合 plant scale、延迟和安全改写，`β=1` 无法区分改善来源。
- 延迟一步时反馈对应更早提议，直接重心化存在相位错配和过度阻尼风险。
- 内部高斯状态到缩放、裁剪物理动作的逆映射必须明确。
- 必须先拆分 proposal、plant rewrite 和 safety rewrite 的 provenance；否则容易以少运动、
  低方差或零动作吸收制造表面改善。

## 主 Agent 筛选

### 立即入选

#### `R0001-P01`：当前谱系无行为改动校准基线

- 状态：`selected / baseline-only`。
- 理由：当前没有行为等价基线，任何能力改动都缺乏归因基础。
- 结论上限：建立当前谱系校准基线；不得宣称家务能力提升。

#### `R0001-P04`：跨 horizon 同步 Episode bootstrap

- 状态：`selected / isolated evaluation repair`。
- 理由：两名评审均确认当前 bootstrap replicate 不共享 Episode multiplicity，统计合同
  不一致。
- 执行顺序：先完成 `P01` 旧统计基线，再在独立分支离线修复；修复接受后重新建立使用
  新统计的基线，不能把旧新差异记作能力增益。

### 条件候选

#### `R0001-P02`：训练 Replay 多时间尺度随机激励

- 状态：`conditional select`。
- 触发：`P01` 至少一个任务或 horizon 的数据 probe 点估计失败，且失败不能由任务样本
  失衡或执行链漂移解释。
- 附加要求：增加未见确认激励、任务×尺度平衡、绝对误差和 jerk/安全守护。

#### `R0001-P05`：跨 source Episode mini-batch

- 状态：`conditional select`。
- 触发：`P01` 所有数据 probe 通过，但单步视觉潜变量或本体动作利用失败。
- 附加要求：冻结 Replay、相同初始化、固定 update，保持同任务同 strata，仅改变 source
  Episode。

### 延后

- `R0001-P03`：只有基线任务计数明显失衡、最弱任务与样本最少任务一致，且均衡子采样
  功效分析支持时再审。
- `R0001-P06`：`P05` 被固定预算否定后再重新设计，当前正式 audit 复刻风险过高。
- `R0001-P08`：先补齐执行链分层 provenance；只有基线失败集中在可区分的改写窗口时再审。

### 拒绝

- `R0001-P07`：当前没有相同整数 seed 导致跨 PRNG 统计混淆的证据，不占用本轮正式实验
  预算。可以做不挑选结果的只读敏感性诊断，但不能作为能力候选。

## 失败指纹路由

1. 先运行 `R0001-P01`。
2. `P01` 在门禁、留出或训练入口失效：先修平台，结果记 `inconclusive`。
3. 数据 probe 点估计失败：
   - 任务样本失衡与失败任务严格重合：先做 `P03` 离线功效诊断；
   - proposal/execution 漂移主导：先补 `P08` provenance；
   - 以上均不成立：进入 `P02` 短物理验证。
4. 数据 probe 全过、世界模型动作利用失败：进入 `P05` 冻结 Replay 重放。
5. `P05` 被否定后才允许重新评审 `P06`。
6. `P04` 始终使用独立评测分支，不与上述能力分支合并。

## 结论边界

即使某候选在固定预算内解锁探索 Actor，本轮最多只能接受“校准瓶颈改善”。只有后续完成
冻结的未见分布闭环物理评测，才能形成家务能力结论。

## 二次共同反驳

### 对 `R0001-P04`

- 同步 bootstrap 只能修正统计合同，`p05` 变化不得计为能力收益。
- 必须在 v4 同一冻结数据上双报告，并验证点估计、MSE、Episode 列表不变。

### 对 `R0001-P02`

- observation lag 提供了比“固定高相关激励不足”更直接的替代解释。
- 在 lag 合同修复前改变 `rho`，会把激励分布与错位敏感度混淆。
- 如果 `P09` 的无丢样本验证使固定 `rho=0.96` 全部过线，`P02` 失去触发条件。

### 对 `R0001-P09`

- v4 离线 lag 对齐是强诊断，但不是最终证据：lag=1、horizon=16 会因旧 shard 缺少
  前置动作而丢样本。
- 必须显式保存 lag 和前置动作，固定样本数，不允许通过删除困难样本过门。
- 只修 action probe；不得同时改 RSSM 或执行头。

### 对 `R0001-P05`

- 跨 source Episode 同时提高每 update 的唯一窗口数，结论只能归因于 batch 组成。
- 它不能修复错误的 action-observation 对齐；只有 `P09` 后数据 probe 全过而世界模型仍
  失败时才可启动。

### 对 `R0001-P10/P11`

- `P10` 检验安全正例稀疏，`P11` 检验 plant latency 的时序表示，必须拆分。
- `P10` 的 0.25 分层会改变联合损失 batch 分布，需保持任务、Episode、碰撞和视觉 strata。
- `P11` 不能使用未来动作或真实延迟标签，且必须在未见 2/3 步延迟确认。

### 对 `R0001-P12/P13`

- 两项都是本轮必须在正式闭环前完成的评测基础设施，不计能力收益。
- `P12` 的 9 条评测文本只能进入 evaluation-only index。
- `P13` 阈值必须在新闭环结果产生前冻结，并与成功率和零严重碰撞联合，防止不运动过门。

## 二次主 Agent 决策

1. 接受 `R0001-P04` 为隔离评测修复，先完成 v4 冻结数据双报告。
2. 立即选择 `R0001-P09`，先做无训练、无丢样本的物理时间对齐验证。
3. 暂缓 `R0001-P02`；若 `P09` 全过则拒绝 `P02`，否则才执行增强后的多尺度短验证。
4. `P05` 只在修正时间合同的数据 probe 全过、世界模型仍失败后启动。
5. `P10` 与 `P11` 保留为独立条件候选；不得互相或与 `P05` 捆绑。
6. `P12/P13` 在首次正式闭环前完成，本轮当前关键路径不先于 `P09`。

## 更新后的失败指纹路由

1. `P04` 双报告不改变点估计/MSE/Episode 列表且负对照通过：接受测量合同。
2. `P09` 固定 `rho=0.96` 和确认 `rho=0.5` 均使全部任务/horizon 过线：
   `P09 accepted as measurement repair`，`P02 rejected without run`。
3. `P09` 无丢样本后仍失败：进入增强 `P02`，再用未见 `rho=0.25/0.75` 确认。
4. 修正数据 probe 全过但 RSSM 动作利用失败：`P05`。
5. 动作执行失败：
   - 自然 Replay 正例稀疏先验证 `P10`；
   - 按 plant latency 分层仍失败且 `P10` 无效，再验证 `P11`。
6. `P12/P13` 只改变评测可执行性和接受合同，不与任何能力候选比较收益。

- 连续 112 的全部合法起点比 7×16 拥有更多有效 h16 回归行，不能把结果表述为训练能力或

### 对 `R0001-P15`

### 对 `R0001-P16`

- 合成 planted effect 若不保留 Episode 自相关、窗口重叠和设计维度，功效结论无效。

- 必须使用因果 latent gate，禁止真实 latency 和未来 proposal，并在未见 2/3 步确认。
