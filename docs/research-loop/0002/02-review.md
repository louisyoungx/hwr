## 共同反驳

### `R0001-P09`

- 事后 lag 重建会丢样本，必须用显式 lag 和完整前置动作重新采集。
- 若只看 ratio，state-only MSE 恶化也可能制造表面通过；必须守护绝对 state-action MSE。
- 只修 data probe，不同时修改 RSSM 或动作执行头。

### `R0001-P10/P11`

- `R0001-P10` 检验类别稀疏，`R0001-P11` 检验时序表示，必须拆分。
- `R0001-P10` 的分层采样会改变联合训练分布，必须保持任务、Episode、碰撞和视觉 strata。
- `R0001-P11` 不能读取真实 latency，且历史长度不得根据未见 latency 结果调参。

### `R0001-P12/P13`

- 两项都是未来正式评测的基础设施，不计能力收益。
- evaluation instruction 不得进入训练。
- 安全干预负担门必须在新闭环结果产生前冻结，不能事后放宽。

## 主 Agent 决策

1. 立即执行 `R0001-P09`。
2. `R0001-P10/P11` 等待 `R0001-P09` 给出稳定时序证据后再路由。
3. `R0001-P12/P13` 独立实施并纳入未来评测合同。
4. 不启动新的正式训练 run；本轮只验证测量与评测合同。

## 结论边界

即使 `R0001-P09` 通过，也只能接受测量修复；不能宣称世界模型、Actor 或家务能力提升。
